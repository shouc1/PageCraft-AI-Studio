# AI 商品图智能生成平台 · 需求分析 v2（产品功能规划）

> 版本：v2.0
> 编写日期：2026-10-10
> 前置文档：[需求分析.md](./需求分析.md)（v1.0，聚焦技术架构与 MVP 闭环，本文不重复其内容）
> 本文定位：**产品级功能规划**——在 v1 技术底座（FastAPI + LangGraph 三专家流水线 + RAG + 即梦生图）之上，规划面向用户的完整功能面，并记录功能评审中识别出的欠缺项与对策。

---

## 1. 功能总览

菜单栏三大功能模块：

| 模块 | 产出 | 核心链路 |
|------|------|---------|
| 主图生成 | 4 张平台主图 | 上传商品图 → 物品识别 → 卖点提取 → 风格选择 → prompt 确认 → 生图 |
| 详情页生成 | 6 张详情图 | 复用主图会话上下文 → 信息结构规划 → prompt 确认 → 生图 |
| 营销文案生成 | 3 套文案方案 | 复用卖点资产 → 热点结合 → AI 生成 → 合规过滤 |

**核心设计原则：三个模块是一个商品会话（Session）的三个视图，不是三个独立工具。**
主图、详情页、文案共用同一份「商品图 + 类目 + 卖点 + 风格」资产；用户在任一模块修改卖点或风格，其余模块同步感知。菜单切换不丢失上下文。

## 2. 主图生成（4 张）

### 2.1 用户原始需求

1. 用户提交商品图片（最多 6 张），识别物品，保持物品不变，识别物品类别。
2. 根据知识库 + 用户提示词，识别主要卖点。
3. 根据用户选择的风格，调用 AI 生成提示词。
4. 用户确认提示词后，调用生图 API 生成主图。

### 2.2 补充设计

#### F-M1 商品图上传与识别
- 上传 1~6 张商品图（复用 v1 F1.1 上传能力，放宽单任务多图）。
- 多图用途：多角度参考（正面/背面/细节/包装），喂给生图 API 作多参考图融合，提升一致性。
- 类目识别：接入现有 5 个类目知识库（`kb/商品类型-*.md`：家居家电 / 数码电子 / 服装鞋包 / 美妆护肤 / 食品饮料），LLM 分类 + 置信度；低置信度时让用户确认类目。

#### F-M2 卖点提取（升级现有专家 1）
- 输入：商品图识别结果 + 类目 + 用户提示词。
- 检索源：`kb/` 类目知识库 + `卖点视觉化词典.md`（**暂不做"网络实时"检索**，热点属文案模块，见 §6.4）。
- 输出：结构化卖点列表（卖点 + 视觉化建议），**展示给用户编辑**——卖点是三个模块共享的资产，必须可人工修正。

#### F-M3 风格选择与 prompt 生成
- 风格来源：`kb/商品海报风格模板.md` + 5 个风格模板（极简ins风 / 日系和风 / 工业复古 / 赛博朋克 / 运动活力），经 RAG 推荐前 3 + 用户自选。
- prompt 生成：复用 v1 F2.6 三专家流水线（分析 → 视觉设计 → 评审循环），卖点列表作为专家 1 的输入注入。

#### F-M4 prompt 确认与生图
- 复用 v1 的 `awaiting_confirmation → confirm` 流程。
- 一次任务生成 4 张：一次提交 4 个生成请求（可同 prompt 出 4 张，或按 4 个不同场景/构图微调 prompt——推荐后者，4 张主图各有侧重：白底/场景/卖点特写/促销）。
- 单张可独立重生成本张，不整组重来（成本控制，见 §6.1）。

## 3. 详情页生成（6 张）

### 3.1 用户原始需求

1. 保持物品不变，用户可提供更详细描述，根据卖点全方位介绍，调用 AI 生成提示词。
2. 用户确认提示词后，调用生图 API 生成详情图。

### 3.2 补充设计（关键缺口：信息结构规划）

**详情页 6 张不是"调用 6 次生成"，而是先规划页面信息结构，再逐张生成。**

#### F-D1 详情页结构规划
- 由类目知识库决定结构模板，例如：
  - 数码电子：场景图 ×2 + 参数特写 ×2 + 功能对比 ×1 + 售后承诺 ×1
  - 服装鞋包：上身场景 ×2 + 材质细节 ×2 + 版型展示 ×1 + 尺码/洗涤信息 ×1
  - 食品饮料：食用场景 ×2 + 配料/产地特写 ×2 + 工艺展示 ×1 + 规格参数 ×1
- 结构规划结果展示给用户，**用户可增删调整每张图的定位**后再进入生成。

#### F-D2 图文混排（重要坑位）
- 详情页通常一半是「图 + 文字排版」（卖点标注、促销标签、参数表），纯生图 API 只能出底图。
- **已定方案：构图留白 + 前端文字层 + 导出合成**：
  - prompt 只负责构图层面留出安全区（不做留白底图单独路线）；
  - 文字 / 标签 / 价格由前端覆盖层渲染（复用 [PreviewCanvas](../frontend/components/studio/PreviewCanvas.tsx) 扩展为文字层组件），可编辑、可换字体、可复用多平台尺寸；
  - 导出时 Canvas 合成 PNG。
- 不采用生图 API 直接画文字：中文错别字 / 笔画变形是常态，电商文字错误即废图。
- 文字内容直接取自卖点资产与文案模块产出，保证三处文案一致。

#### F-D3 prompt 确认与生成
- 每张图独立 prompt（基于该图在结构中的定位 + 共享卖点），批量确认后批量提交。
- 同样支持单张重生成。

## 4. 营销文案生成（3 套方案）

### 4.1 用户原始需求

1. 根据卖点 + 网络实时热点，调用 AI 生成文案。

### 4.2 补充设计

#### F-C1 文案生成
- 输入：商品会话的卖点资产 + 类目 + 用户补充要求。
- 输出：3 套差异化方案（建议定位：卖点直述型 / 场景种草型 / 促销转化型），每套含主图文案 + 详情页文案 + 短标题，可直接回填到详情页文字层。

#### F-C2 合规过滤（必做，不可省）
- 广告法极限词过滤：「最」「第一」「国家级」「顶级」等（结合 `kb/电商合规规则.md`）。
- 双层实现：LLM 生成时 system prompt 注入合规规则 + 生成后规则词库硬校验，命中词标红替换建议。

#### F-C3 热点来源（已定方案）
- **P1 用静态热点源**：「节日 / 节气 / 大促日历」知识库维护（如"临近双 11，突出囤货场景"），零外部依赖。
- **P2 采用豆包 web search 插件**：ARK 联网工具在文案生成调用时开启，热点获取与文案生成合成一次 LLM 调用——不自建检索模块、不爬热榜（反爬维护成本高且合规灰色）、无需额外搜索 API。
- 联网结果仍需过 F-C2 合规过滤。

## 5. 关键技术专项：物品一致性（最大风险项）

「保持物品不变」在原始需求中是前提，实际是**整个产品最难的一环**，必须升级为显式技术方案：

| 风险表现 | 说明 |
|---------|------|
| LOGO/文字失真 | 生成图中商品品牌 LOGO 糊掉、瓶身文字变形——电商场景零容忍，构成违规 |
| 颜色/形状偏移 | 商品本体被 AI"再创作"，与实物不符涉嫌虚假宣传 |
| 多图一致性 | 4 张主图 / 6 张详情图之间的商品外观互相不一致 |

**对策（已定方案：压低重绘强度，不做原图回贴）**：
1. **主方案 · 低强度高保真垫图**：即梦 i2i 接口 `scale`（重绘强度）压低到 0.3~0.5，商品本体尽量保留原图像素，AI 主要重绘背景与氛围（现有 image2image workflow 扩展，多参考图支持同步加上）。
2. **一致性校验环节**：生成后对结果图与原图做相似度比对（视觉 embedding），低于阈值自动标记"疑似失真"提示用户复查。
3. **兜底 · 局部重绘**：个别失真区域（LOGO、文字）由用户蒙版框选后走 inpaint 单独修复，或前端直接贴回原图该区域。
- 不采用整图分割回贴（rembg/OpenCV 合成）：分割质量在反光/透明/毛绒材质上不可控，且低强度方案已覆盖主要场景，不为小概率场景引入复杂管线。

## 6. 横向能力（原方案欠缺项）

### 6.1 重生成与成本控制
- 生图按张计费（约 ¥0.1~0.3/张），用户不满意率必然不低。
- 必须：单张重生成 / 局部重绘（inpaint，前端已有 [InpaintMaskEditor](../frontend/components/studio/InpaintMaskEditor.tsx) 骨架）/ 整组重生成三级粒度。
- 展示单任务预估费用，重生成前二次确认。

### 6.2 批量与 SKU
- 一个商品多颜色/多尺码时，主图常需 6 图 × N SKU。
- 会话模型预留 SKU 维度：同商品不同 SKU 图可作为变体批量生成（P1，MVP 先单 SKU）。

### 6.3 任务管理
- 分钟级异步任务 + 多张批量生成，复用 v1 任务体系并扩展：
  - 任务支持子任务（一张图 = 一个子任务，父任务聚合进度）。
  - 失败子任务独立重试，不拖垮整组。
  - 会话级历史：按商品会话归档任务，而非散落任务列表。

### 6.4 数据模型扩展：商品会话 `product_sessions`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT (UUID) | 主键 |
| name | TEXT | 商品名（用户填或 LLM 生成） |
| category | TEXT | 识别类目（可人工修正） |
| images | TEXT (JSON) | 商品图 image_id 列表（1~6 张） |
| selling_points | TEXT (JSON) | 卖点资产（结构化，用户可编辑） |
| style | TEXT | 选定风格 |
| status | TEXT | draft / generating / done |
| created_at / updated_at | DATETIME | |

任务表 `tasks` 增加 `session_id` 外键。主图/详情页/文案任务均挂到同一会话。

### 6.5 规格与合规约束（电商硬约束，必须在生成前生效）

| 约束 | 来源 | 落点 |
|------|------|------|
| 主图 1:1（800×800 起），平台各异 | `kb/电商主图规范.md` | 生图尺寸参数 + 裁切/外扩补画后处理 |
| 详情页宽 750/790px | 同上 | 底图生成比例 + 文字层画布规格 |
| 白底图（平台第 5 张惯例） | 同上 | 固定模板 prompt，不走自由风格 |
| 广告法极限词 | `kb/电商合规规则.md` | 文案硬校验 + prompt 生成时注入禁令 |

## 8. 优先级建议

| 阶段 | 内容 | 说明 |
|------|------|------|
| P0 | 商品会话 + 主图生成全链路（含卖点编辑、prompt 确认、单张重生成） | 先跑通一个模块闭环 |
| P0 | 一致性方案落地（§5：低强度垫图 + 失真校验） | 跟随主图链路实现，不通过不上详情页 |
| P1 | 详情页生成（结构规划 + 前端文字层） | 依赖一致性方案过关 |
| P1 | 文案生成（3 方案 + 合规过滤，热点用静态日历） | 独立性强，可并行 |
| P2 | SKU 批量、实时热点（豆包联网插件）、多平台尺寸适配 | 二期 |

## 9. 已决策事项（原开放问题）

| # | 问题 | 决策 |
|---|------|------|
| 1 | 图文混排技术路线 | **前端文字层**：prompt 构图留白 + 前端覆盖层渲染文字/标签/价格，导出时 Canvas 合成 PNG。不用生图 API 直接画中文文字（错字率高即废图），不做留白底图单独路线。详见 F-D2。 |
| 2 | 原图回贴分割质量 | **不实测、不做回贴**：直接采用压低重绘强度方案（i2i `scale` 0.3~0.5 保真垫图）+ 失真校验 + inpaint 局部兜底。详见 §5。 |
| 3 | 热点数据源 | **不自建热点模块**：P1 用静态节日/大促日历（知识库维护）；P2 若立项，用豆包 web search 插件（ARK 联网工具），热点获取与文案生成合并为一次 LLM 调用，结果过合规过滤。详见 F-C3。 |
| 4 | 即梦并发配额 | **不做并行赌配额，做可配置排队**：后端 `asyncio.Semaphore` 信号量限流（配置项 `JIMENG_MAX_CONCURRENCY`，默认值按火山控制台实际配额填写），一图一子任务统一过队列；重试同样过信号量防风暴；排队进度经现有 WebSocket 推送（"第 2/4 张生成中"）。配额升级只改配置不改代码。 |
